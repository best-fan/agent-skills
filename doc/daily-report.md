# Daily Report 技能文档

## 使用时机

在以下情况使用此技能：

- 用户请求生成日报、工作总结、提交记录汇总
- 手动调用 `/daily-report` 命令
- 用户询问"今天做了什么"、"工作进度"等
- 需要将当日 Git 提交记录归纳为可粘贴到 OA 系统的纯文本日报

---

## 核心功能

- 获取 Git 用户信息（用户名、邮箱），筛选当日提交记录（含 commit body）
- 支持今天、昨天、自定义日期统计
- 推断业务模块并经用户确认，作为日报条目前缀
- 按工作主题归纳为「动作+对象」条目，去掉 commit type 前缀
- 输出 reportContent 风格的序号列表（顿号串联），可直接粘贴到 OA 系统

---

## 执行步骤

### 步骤 1：获取 Git 用户信息

```bash
git config user.name
git config user.email
```

用于筛选当前用户的提交记录，避免包含他人的提交。

---

### 步骤 2：询问统计日期

使用 `AskUserQuestion` 让用户选择统计日期：

| 选项 | 说明 |
|------|------|
| 今天（默认） | 当天日期，格式 YYYY-MM-DD |
| 昨天 | 昨天日期，格式 YYYY-MM-DD |
| 自定义日期 | 用户输入指定日期 |

将选择解析为 YYYY-MM-DD 格式。

---

### 步骤 3：获取提交记录

获取指定日期的提交记录（**含 commit body**，供后续归纳使用）：

```bash
git log --author="<用户名>" --since="<日期> 00:00:00" --until="<日期> 23:59:59" --format="%h %s%n%n%b"
```

> 若当天无提交记录，进入「兜底处理」流程。

---

### 步骤 4：推断并确认业务模块

根据提交记录推断当天所属业务模块（如 oa、KPI项目、标准框架、档案管理、工会小程序等），再用 `AskUserQuestion` 让用户确认或修改。

询问措辞参考：

> 检测到今天工作集中在「{模块}」模块，是否正确？可直接修改为其他模块名。

用户确认后，将该模块作为当天默认前缀。**跨多个模块时，为每个工作条目各自标注所属模块前缀，不强制统一为单一模块。**

模块前缀推断优先级见下方「模块前缀推断规则」。

---

### 步骤 5：归纳工作内容

将当天提交记录按工作主题归纳为若干条目：

- 合并同一功能/模块的多条提交
- 去掉 commit type 前缀（feat/fix/chore/docs 等），浓缩改写为「动作+对象」
- 措辞贴近真实 reportContent 的口语化风格（参考「reportContent 风格示例库」）
- 同一条目内的多个细节用顿号「、」串联

详细规则见下方「归纳规则」。

---

### 步骤 6：输出序号列表

按以下格式输出日报（纯文本，可直接粘贴）：

```text
1、{模块-}{工作内容1}、{工作内容2}
2、{模块-}{工作内容3}
3、{工作内容4}
```

输出要求：

- 每条以 `N、` 开头（N 从 1 递增，后接中文顿号）
- 业务模块作前缀：`模块-`（无明确归属的条目不加前缀）
- 同主题细节用顿号「、」串联
- **不输出** `统计：`、`其他：` 等附加行

---

## 归纳规则

| 规则 | 说明 |
|------|------|
| 合并 | 同一功能/模块的多条 commit 合并为一条，避免逐条罗列 |
| 浓缩 | 去掉 commit type 前缀，改写为「动作+对象」 |
| 措辞 | 贴近 reportContent 口语化风格，避免技术黑话堆砌 |
| 顿号串联 | 一条目内多个细节用「、」连接，不使用分号或逗号 |
| 条目数 | 通常 2-6 条，按工作主题划分，不严格等于 commit 数量；commit 仅 1-2 条时直接输出，不过度归纳 |

**浓缩示例：**

| 原始 commit | 归纳结果 |
|-------------|----------|
| `fix: 修复选人组件 indexOf 空值崩溃` | `修复选人组件搜索空值崩溃` |
| `feat: 新增考评卡片` | `新增考评卡片` |
| `chore: 升级依赖版本` | `升级依赖版本` |

---

## 模块前缀推断规则

按以下优先级推断业务模块名：

1. **手写前缀**：从 commit message 开头的手写前缀提取（如 `oa-xxx`、`KPI项目-xxx`、`档案管理-xxx`）
2. **commit scope**：从规范的 `<type>(<scope>):` 中提取 scope 并映射为业务模块名（如 `feat(oa):` → `oa`）
3. **目录/内容推断**：根据仓库目录名或 commit 内容语义推断（如目录含 `archive` → `档案管理`）

> 推断后**必须用 `AskUserQuestion` 向用户确认**，不擅自假定。

## reportContent 风格示例库

以下为真实 reportContent 样例，归纳时对齐其风格（模块前缀 + 顿号串联 + 浓缩口语化）：

- `oa-启用权限参数更新逻辑、修复回收站列表 API 接口路径、移除旧流程设计组件及相关依赖`
- `标准流程引擎-完成本地组件库迁移（拆分构建+重构依赖引用），版本升至 v3.4.1`
- `档案管理-借阅统计相关页面接口调试、写借阅记录与下载列表功能接口`
- `KPI项目-业务经理面板项目概况、项目详情结算金额下钻、select 切换优化`

---

## 兜底处理

| 场景 | 处理方式 |
|------|----------|
| 当天无提交 | 提示"当天无 Git 提交记录"，用 `AskUserQuestion` 询问是否手动输入工作内容 |
| 提交仅 1-2 条 | 直接逐条输出，不过度归纳 |
| 用户需要统计信息 | 默认不输出统计行；若用户明确要求，在序号列表后追加可选附注（如 `（共 X 次提交）`） |

## 输出示例

### 示例一：单模块，多条提交归纳

```text
1、oa-修复选人组件搜索空值崩溃、新增考评卡片、修复绩效计算逻辑
2、oa-完善权限参数更新逻辑、移除旧流程设计组件及相关依赖
```

### 示例二：跨模块

```text
1、oa-启用权限参数更新逻辑、修复回收站列表 API 接口路径
2、标准框架-人员选择器缩放加载问题处理、文件上传组件上传拦截校验
3、完善设计清单生成技能、验证生成效果
```

> 第 3 条无明确模块归属，不加前缀。

## 技术要点

| 要点 | 说明 |
|------|------|
| 用户名获取 | 使用 `git config user.name` |
| 完整提交信息 | 使用 `--format="%h %s%n%n%b"` 获取含 body 的提交信息，支撑 AI 归纳 |
| 日期格式 | 统一为 YYYY-MM-DD |
| 时间范围 | 00:00:00 至 23:59:59 |
| 模块前缀 | 必须经用户确认，不擅自假定 |
| 序号格式 | `N、`（中文顿号），从 1 递增 |

## 版本信息

- 当前版本：2.0.0
- 更新日期：2026-07-21

### v2.0.0 主要变化

相较 v1.0.0，本版本重新定位为「生成可直接粘贴到 OA 系统的 reportContent 风格日报」：

- **输出形态**：由「scope 分组 + 统计行」改为「业务模块前缀 + 序号列表（顿号串联）」
- **归纳方式**：由按 scope 机械分组改为 AI 按工作主题归纳，浓缩为「动作+对象」
- **统计信息**：默认不再输出提交次数与增删行数；仅在用户明确要求时作为可选附注
- **模块确认**：新增业务模块推断与用户确认环节
