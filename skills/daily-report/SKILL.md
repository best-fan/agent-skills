# Daily Report Skill

从 Git 提交记录出发，经 AI 归纳生成 reportContent 风格的工作日报。输出为序号列表，按业务模块标注前缀，可直接粘贴到 OA 系统的 reportContent 字段。

## 核心约定（NON-NEGOTIABLE）

- **只扫描当前用户的提交**：在 Git 仓库中统计提交记录时，必须按当前 Git 用户（name 与 email）过滤，只归纳当前用户自己的提交，绝不把他人的提交混入日报
- 若目录不是 Git 仓库，则跳过 Git 流程，直接询问用户手动输入工作内容

## 使用场景

此 Skill 在以下情况下触发：

- 用户请求生成日报、工作总结、提交记录汇总
- 用户运行 `/daily-report` 命令
- 用户询问"今天做了什么"、"工作进度"等

## 执行步骤

### Step 1: 获取 Git 用户信息

确认当前目录是 Git 仓库后，获取当前 Git 用户名和邮箱。二者共同用于筛选**当前用户**的提交记录：

```bash
git config user.name
git config user.email
```

若 `user.name` 或 `user.email` 为空，改用以下方式确定作者标识：

```bash
# 取当前用户最近一次提交的作者信息
git log -1 --format="%an|%ae"
```

仍无法确定时，用 AskUserQuestion 让用户手动输入用于筛选的作者名或邮箱。

### Step 2: 询问统计日期

用 AskUserQuestion 询问用户统计日期，提供三个选项：

- 今天（默认，格式 YYYY-MM-DD）
- 昨天（格式 YYYY-MM-DD）
- 自定义日期

将用户选择解析为 YYYY-MM-DD 格式的日期。

### Step 3: 获取提交记录

使用 Git 命令获取指定日期**当前用户**的提交记录（含 commit body，供归纳使用）。

同时按用户名和邮箱过滤（多个 `--author` 为 OR 关系），避免因 author name 与 `git config user.name` 不一致而漏掉自己的提交：

```bash
# 只获取当前用户的提交（按 name 和 email 双重匹配，含正文 body）
git log --author="<用户名>" --author="<邮箱>" --since="<日期> 00:00:00" --until="<日期> 23:59:59" --format="%h %an | %s%n%b"
```

注意：

- 必须带 `--author` 过滤，禁止统计全仓库所有人的提交
- 输出中包含作者名 `%an`，用于最终核对所有条目均属当前用户
- 若筛选结果为空，进入「兜底处理」流程，先排查是否为作者名不匹配

### Step 4: 推断并确认业务模块

根据提交记录推断当天所属业务模块（如 oa、KPI项目、标准框架、档案管理、工会小程序等），然后用 AskUserQuestion 让用户确认或修改。

推断优先级见「模块前缀推断规则」。询问措辞参考：

> 检测到今天工作集中在「{模块}」模块，是否正确？可直接修改为其他模块名。

用户确认后，将该模块作为当天默认前缀。若当天提交跨多个模块，为每个工作条目各自标注所属模块前缀。

### Step 5: 归纳工作内容

将当天提交记录按工作主题归纳为若干条目：

- 合并同一功能/模块的多条提交
- 去掉 commit type 前缀（feat/fix/chore/docs 等），浓缩改写为「动作+对象」
- 措辞贴近真实 reportContent 的口语化风格（参考「reportContent 风格示例库」）
- 同一条目内的多个细节用顿号「、」串联

详细规则见「归纳规则」。

### Step 6: 输出序号列表

按格式输出日报（纯文本，可直接粘贴）：

```text
1、{模块-}{工作内容1}、{工作内容2}
2、{模块-}{工作内容3}
3、{工作内容4}
```

输出要求：

- 每条以 `N、` 开头（N 从 1 递增，后接中文顿号）
- 业务模块作前缀：`模块-`（无明确归属的条目不加前缀）
- 同主题细节用顿号「、」串联
- 不输出 `统计：`、`其他：` 等附加行

## 归纳规则

- **合并**：同一功能/模块的多条 commit 合并为一条，避免逐条罗列
- **浓缩**：去掉 commit type 前缀，改写为「动作+对象」。示例：
  - `fix: 修复选人组件 indexOf 空值崩溃` → `修复选人组件搜索空值崩溃`
  - `feat: 新增考评卡片` → `新增考评卡片`
  - `chore: 升级依赖版本` → `升级依赖版本`
- **措辞**：贴近 reportContent 口语化风格，避免技术黑话堆砌，参考「reportContent 风格示例库」
- **顿号串联**：一条目内多个细节用「、」连接，不使用分号或逗号
- **条目数**：通常 2-6 条，按工作主题划分，不严格等于 commit 数量；commit 仅 1-2 条时直接输出，不过度归纳

## 模块前缀推断规则

按以下优先级推断业务模块名：

1. **手写前缀**：从 commit message 开头的手写前缀提取（如 `oa-xxx`、`KPI项目-xxx`、`档案管理-xxx`）
2. **commit scope**：从规范的 `<type>(<scope>):` 中提取 scope 并映射为业务模块名（如 `feat(oa):` → `oa`）
3. **目录/内容推断**：根据仓库目录名或 commit 内容语义推断（如目录含 `archive` → `档案管理`）

推断后必须用 AskUserQuestion 向用户确认。跨模块时，每条目各自带前缀，不强制统一为单一模块。

## reportContent 风格示例库

以下为真实 reportContent 样例，归纳时对齐其风格（模块前缀 + 顿号串联 + 浓缩口语化）：

- `oa-启用权限参数更新逻辑、修复回收站列表 API 接口路径、移除旧流程设计组件及相关依赖`
- `标准流程引擎-完成本地组件库迁移（拆分构建+重构依赖引用），版本升至 v3.4.1`
- `档案管理-借阅统计相关页面接口调试、写借阅记录与下载列表功能接口`
- `KPI项目-业务经理面板项目概况、项目详情结算金额下钻、select 切换优化`

## 兜底处理

按作者筛选后无提交时，先运行一次不带 `--author` 的查询区分「没提交」与「没匹配上」：

```bash
# 查看当天仓库内所有人的提交作者分布
git log --since="<日期> 00:00:00" --until="<日期> 23:59:59" --format="%an <%ae>" | sort | uniq -c
```

- **当天仓库无任何提交**：提示用户"当天无 Git 提交记录"，用 AskUserQuestion 询问是否手动输入工作内容
- **当天有他人提交、但按当前用户筛选为 0 条**：提示"当天仓库有 N 条他人提交、你的提交为 0 条"，可能为作者名不匹配，用 AskUserQuestion 让用户确认作者标识（或从上面的作者分布中选择），再重新筛选；确认后仍无提交则视为当天无提交
- **提交仅 1-2 条**：直接逐条输出，不过度归纳
- **用户需要统计信息**：默认不输出统计行；若用户明确要求，在序号列表后追加可选附注（如 `（共 X 次提交）`）

## 技术要点

- **必须用 `--author` 过滤为当前用户的提交**（name 与 email 双重匹配），禁止扫描全仓库所有提交
- 使用 `git config user.name` / `git config user.email` 获取当前用户标识，为空时回退到 `git log -1 --format="%an|%ae"`
- 使用 `--format="%h %an | %s%n%b"` 获取含作者与 body 的完整提交信息，支撑核对与归纳
- 日期格式统一为 YYYY-MM-DD
- 模块前缀必须经用户确认，不擅自假定
